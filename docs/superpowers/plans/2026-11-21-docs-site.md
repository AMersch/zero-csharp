# Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An FsLiveDocs documentation site for zero-mode C# on the bflat fork, built like FCQRS's, published to GitHub Pages.

**Architecture:** Markdown pages under `docs/` are assembled by `scripts/build-docs.py` into `.livedocs/content/`, rendered by FsLiveDocs 0.7.3 (with a placeholder F# project it requires), then post-processed: C# colouring scripts injected, the empty F# API page dropped, assets and the landing page copied, Pagefind indexing, link check. C# excerpts are tied to sample regions by `scripts/check-doc-snippets.py`; reference pages are generated from `lib/*.cs` by `scripts/gen-reference.py`.

**Tech Stack:** FsLiveDocs 0.7.3 (dotnet tool), Python 3, Node (npx pagefind@1.5.2), highlight.js (vendored from FCQRS), GitHub Actions + Pages.

**Spec:** `docs/superpowers/specs/2026-11-21-docs-site-design.md`

## Global Constraints

- C# only; no F# content. The placeholder F# project exists only because FsLiveDocs needs one.
- The docs build needs only .NET 10 SDK, Python 3 and Node 22: never bflat, Docker or emulators.
- Code lines in `csharp` fences: at most 80 columns.
- Every `csharp` fence on a page is preceded by a `<!-- sample: <path> <region> -->` marker, except fences
  explicitly marked `csharp no-sample` (for signatures and fragments that can't be a sample region).
- `docs/llama-plan.md` and `docs/superpowers/` are never part of the site.
- Prose style: the repository's (plain, direct, concrete; see README.md). No marketing language.
- Document the arena API as it is in the working tree (`OpenScope`/`Scope`, named arenas, `Dump`,
  `PeakUsed`/`PeakCapacity`, `stopOnOutOfMemory`, `Guards`).

## Review Focus

- A page link to another page or a heading that doesn't exist → link check fails the build.
- A sample edited after a page quoted it → snippet check fails and names page, sample and region.
- A `docs:` region marker left unclosed, or a page naming a region that doesn't exist → check fails with that name, not a Python traceback.
- Dark theme: C# code colours readable in both themes (palette defined for both in site.css).
- Reference generator meeting a public member with no `///` comment → page lists it with its signature, and the generator prints a warning.

### Task 3: Reference generator

**Files:** Create `scripts/gen-reference.py`; output `docs/reference/*.md` (generated, git-ignored) and a
hand-written `docs/reference/index.md`.

**Interfaces — Produces:** one page per public top-level type in `lib/*.cs`: `# TypeName` (kind,
source file link), the type's `///` summary/remarks, then each public member (and public nested types) as
a `csharp no-sample` signature block followed by its summary, `<param>`, `<returns>`, `<remarks>`,
`<safety>` text.

- [ ] Parse source, not XML (keeps signatures as written): a public declaration line at type or member
  depth, with the contiguous `///` block above it. Strip expression bodies (`=> …;`) and bodies `{ … }`
  from shown signatures. Convert `<see cref="X"/>`, `<paramref name="x"/>`, `<c>`, `<code>` to Markdown.
- [ ] Warn (stderr) for each public member without a comment; don't fail.
- [ ] Wire into `build-docs.py`; verify `output/reference/arena.html` lists `OpenScope`, `Scope`, `Dump`.
